Written by the session that executed `PKG-05-grader-check-tool.md`. Read by every later package that depends on 05. Keep every heading, even if the answer is "none".

## What changed

A `grader` agent (`agents/grader.py`, gemini-2.5-flash-lite, tool-less, flat 4-field `GraderOutput`) judges each rubric item of one answer yes/no against the stored reference, and `grade()`, its only caller, runs ONE second opinion on the `grader_second` slot (gemini-2.5-flash, thinking 0) when confidence is below `GRADER_SECOND_OPINION_CONFIDENCE`. Every grader failure (budget, validation, provider or network outage, an answer over `GRADER_ANSWER_MAX_CHARS`, an item with no rubric, a second opinion still below the floor) degrades to `GradeResult(unavailable=True)` plus a WARNING, and every billed run, failed or not, leaves one `llm_usage` row. `agents/tools/check.py::grade_answer` is the single grading ROUTE helper (A16): it turns one explicit submission into a code-side `GradeOutcome`, appends one PKG-03 `Evidence` dict to `deps.pending_evidence`, and never persists (inv_14). It runs the grader for both outcomes of an `mc_reason` option and of the numeric gate, so an unavailable grader records nothing for either outcome (inv_28), and code never issues "correct" on a strong channel. `Evidence.grader_backend` with its `node_mastery_events.grader_backend` column and `learning/evidence.py::flush_pending`, the route's one-call persister, land as PKG-03 reopens, and `GRADER_RETRY_BELOW` is renamed `GRADER_SECOND_OPINION_CONFIDENCE` (PKG-01 reopen). Both grader slots have a deterministic function-mode handler, and `tests/evals/grader.py` (8 cases) gates reference leakage, strictness and rubric agreement. Nothing registers or calls `grade`, `grade_answer` or `flush_pending` yet (pinned by `test_nothing_calls_the_grading_helpers_yet`) and `grade_answer` is inert when `deps.learning_loop` is False, so every request path is byte-identical with `LEARNING_LOOP_ENABLED` unset, false or true.

Usage: one `llm_usage` row per run through `record_agent_usage` (`task="grader"` / `"grader_second"`), including a run that raised after at least one billed response (the token cap is checked after the response); a run that got no response records nothing. - `backend/agents/tools/check.py::grade_answer` — canonical signature, which PKG-05b, 07, 08, 10, 12 and 14 take from here:
  `async def grade_answer(item: CheckItem, answer: CheckAnswer, *, deps: SaplingDeps, node_id: str, max_rung: int = 0, same_session_recheck: bool = False) -> GradeOutcome`.
  In order: `deps.learning_loop` False → `GradeOutcome(unavailable=True)`, nothing called. `max_rung` outside `0..LADDER_MAX_RUNG` → `ValueError`, and an unknown `item.format` → `KeyError`, both before any grader call. Idk → `Evidence(idk=True, correct=False, channel=<item's>, grader_backend=None, confidence=None)`, no grader call. Otherwise `grade(item, format=item.format, student_answer=...)`, where the `mc_reason` student answer is `"Selected option: <opt>\nReason: <reason>"`. An unavailable result → `GradeOutcome(unavailable=True)` and nothing appended. `correct` = `all_yes`; for `mc_reason`, `all_yes` AND the selected option equals `item.correct_option` (casefolded, whitespace-collapsed, and never on an empty selection). The numeric gate (see below) overrides a clear mismatch to incorrect. `wrong_key` (A22) is None when the answer is correct or nothing matched. For `free`/`teachback` it is the grader's key. For an `mc_reason` wrong option it is that option's `wrong_key` only when it equals the grader's key, else None. For the right option with a failed reason it is the grader's key. The appended row is `Evidence(...).model_dump()` with `node_id`, the channel, `max_rung`, `session_id=deps.session_id`, `check_item_id=item.id`, `question_hash=item.question_hash`, `same_session_recheck`, `correct`, `confidence` and `grader_backend`. `assisted` and `weight` are DERIVED by PKG-03's model (any rung ≥ `RUNG_ASSISTED_MIN` → assisted; the weight is `evidence_weight`: assisted only on a correct answer, re-check, the grader's confidence for BOTH outcomes, and 0.0 for a correct answer at ≥ `RUNG_NO_CREDIT_MIN`, which is still appended). The numeric gate applies to non-`mc_reason` items with `answer_kind == "numeric"`, `canonical_verified` true, both numbers finite floats, and `|answer − canonical| > (tolerance or 0.0) + _EDGE_SLACK × max(1, |answer|, |canonical|)` (`_EDGE_SLACK = 1e-12`: float noise, so an answer exactly `tolerance` away keeps the grader's verdict on both sides): the answer is then incorrect with `grader_backend="deterministic"` and `confidence=None`, and the grader's matched key still feeds `wrong_key`. It never issues "correct".
