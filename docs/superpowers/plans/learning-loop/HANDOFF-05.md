Written by the session that executed `PKG-05-grader-check-tool.md`. Read by every later package that depends on 05. Keep every heading, even if the answer is "none".

## What changed

A `grader` agent exists (`agents/grader.py`, task `"grader"`, gemini-2.5-flash-lite, tool-less, `retries=2`, flat 4-field `GraderOutput`). It sees the stored reference answer, judges each rubric item yes/no, never solves the problem and never restates the key. `grade()` is the only caller of the agent. It runs under `GRADER_LIMITS`, records one `llm_usage` row per run (`task="grader"` / `"grader_second"`), and runs ONE second opinion on the `grader_second` slot (gemini-2.5-flash, thinking 0, same agent and prompt) when confidence is below `GRADER_SECOND_OPINION_CONFIDENCE`. A budget, output-validation or provider failure degrades to `GradeResult(unavailable=True)` plus a WARNING, and so does a second opinion that is still below the floor. `agents/tools/check.py::grade_answer` is the single grading ROUTE helper (A16). For one explicit submission it builds a code-side `GradeOutcome` and appends one PKG-03 `Evidence` dict to `deps.pending_evidence`. It is inert when `deps.learning_loop` is False. An idk answer becomes incorrect evidence on the item's channel with no grader call (A1). The grader runs for both outcomes of an `mc_reason` option and of the numeric gate, and the mc option is compared in code. The numeric gate runs after the grader and can only ever say "incorrect" (`grader_backend="deterministic"`). An unavailable grader appends nothing for either outcome (inv_28), and `grade_answer` never persists (inv_14). `Evidence.grader_backend` and the `node_mastery_events.grader_backend` column exist (PKG-03 reopen). `learning/evidence.py::flush_pending` is the route's one-call persister (PKG-03 reopen). `GRADER_RETRY_BELOW` is renamed `GRADER_SECOND_OPINION_CONFIDENCE` (PKG-01 reopen). Both grader slots have a deterministic function-mode handler. `tests/evals/grader.py` is recorded and baselined. Nothing registers or calls `grade`, `grade_answer` or `flush_pending` yet, so every request path is byte-identical with `LEARNING_LOOP_ENABLED` unset, false or true.
