## What changed

`backend/services/ai_budget.py` enforces the owner-approved per-student AI caps and the degradation ladder of spec §3.5 from ONE paged `llm_usage` read per request, and never calls a model: the band-aware daily $ (novice ×2.5), the monthly $, daily tokens, the per-session tutor and deep request caps, the grader cap, a per-user rate limit, and an alert-only platform check. `ai_budget.check(` runs first at every `grader`, `grader_second` and `decision` run site (reopen commits of PKG-05 and PKG-05b), so a capped attempt is `unavailable` and writes no evidence for either outcome (invariant 28's cap half), and invariant 23 pins "a budget check before every budgeted agent run" by AST scan. `enforce_rate_limit` is a ready FastAPI dependency (and `enforce_rate_limit_for` its inline form); `main.py` maps `AIBudgetExceeded` to HTTP 429 `{"detail": "ai budget reached", "reset_at": …, "scope": …, "request_id": …}` with `Retry-After`. `ai.budget_capped` is in the event taxonomy and fires for every cap hit (each triggered scope, not only the one the decision reports), at most once per process per (user, scope, level, UTC day). Every `llm_usage` row now records `cached_tokens` and `thinking_tokens` (NULL when unmeasured) and bills cached input at the cached rate (A21). Nothing a student sees changes (one exception: A21's cached rate lowers the `cost_usd` the legacy quiz spend cap sums — Known gaps): no route calls `check` or attaches the dependency (PKG-07 does), and the grader/decision sites are reached only from the dark loop path; with `LEARNING_LOOP_ENABLED` unset, false or true every route behaves as before. The app now loads `learning.policy` and `learning.ladder` at boot (ai_budget imports policy's type aliases and `main.py` registers the handler), which PKG-06 reopens sanction in PKG-06's inertness pins (exactly that import statement and exactly that loaded pair).
