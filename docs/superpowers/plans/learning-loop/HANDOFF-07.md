## What changed

The loop tutor exists as ONE agent with ONE system prompt (`agents/loop_tutor.py::loop_tutor_agent`, the two read tools only) whose tier slot — `loop_tutor_lite` (2.5 Flash-Lite), `loop_tutor` (2.5 Flash, thinking 0) or `loop_tutor_deep` (2.5 Pro, thinking 1024) — is chosen per run in code from `learning.policy.model_tier`, after `services.ai_budget.check` has read the student's budget in the same function (invariant 23), with `max_tokens` = thinking + 400 and `LOOP_LIMITS` 4/3/40K. Phase, band format, turn shape, rung ceiling and — in feedback — the grader's verdict ride a user-message prefix (`phase_prefix`, which has no parameter that could carry a reference answer). `routes/learn_loop.py` is mounted at `/api/learn/loop` (every endpoint `require_self` + the gate's 404, the A20 rate-limit dependency on the seven model-calling routes, the session checked to be the requester's): status, chat (JSON + SSE), start-session (+ stream), action, step/attempt, hint, check/answer (+ stream) and check/next. `/check/answer(/stream)` is the only loop-chat evidence path: `grade_answer` → ONE `flush_pending` → ONE feedback turn with the verdict in the prefix; idk and non-attempt phrases route per A16 through `gates.non_attempt_phrases`. The check pose, the H2/H4/H6 payloads (leak-checked against the active item's structured final answer before emission, A17/A34), the hard-level feedback and opener templates and the "couldn't check" reply are served with no model call; model-written text is leak-checked and stripped before it persists (`done.reply` is the stripped text). `_activate_next_item` (A27) is the only writer of the active item and runs after `LOOP_TEACH_TURNS_BEFORE_CHECK` served teach turns or on `POST /check/next`; teach turns take the current plan concept's band. Every legacy `/api/learn/*` handler delegates to the loop router when the gate is true and is byte-identical when it is false (pinned call-sequence snapshot). Five stream event types (`phase`, `check`, `hint_offer`, `learner_state`, `budget`) are yielded around the unchanged `stream_agent_turn` ladder. `rag_service.chunks_for_ids` resolves an item's source chunks for one named reader under the #629 visibility rule, and `loop_state_store.seen_hashes` / `revealed_hashes` feed item exclusion (A23). With `LEARNING_LOOP_ENABLED` unset nothing a student sees changes: the gate reads nothing, every delegation line is a no-op, `/api/learn/loop/*` is 404 (E2E: 89 passed, 13 skipped, oracles 0 findings).
