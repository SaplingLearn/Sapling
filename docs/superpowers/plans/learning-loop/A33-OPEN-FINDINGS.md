## 1. major — `backend/learning/answer_guard.py:1485`

Findings 1 and 4 are only partly resolved. 7964da5 removed the connectives and quantifiers from _ANSWERING_WORDS. It kept the modals and polarities, and finding 4's description names 'can', 'will' and 'not'. So a pure completeness claim made of function words plus a modal the item uses still passes the code check inside a longer answer: 'That would be it.', 'That can be it.', 'That will do.', 'That should do it.'. Before edec508 these returned None. The rule 'substance only in a span with no claim word' does not catch them, because a claim like that has no word from the list. This is the same shape as 'Mark each.', which review round 4 rated major: credit on the tail rests on the span check alone, which breaks ruling point 1. No test pins it and HANDOFF Known gaps does not record it.

**Evidence:** support_span(tail, PARTIAL + ' ' + tail, min_chars=4, min_share=0.5, context=reference) over the 54 reference answers in the check_items cassettes (22 of them use a polarity or modal). 'That would be it.' passes on 9 of 54, 'That can be it.' on 4, 'That will do.' on 2, 'That should do it.' on 1. At edec508^ every one passes on 0. Through the real grade() with tests/grader_fakes (item reference '…the calls would never end and the stack can overflow.'; the first run credits both items, quoting the partial answer for r1 and the tail for r2): 'That would be it.' gives span message ["It's the case where the function stops recursing", 'That would be it'] and {'r1': True, 'r2': True} with the default agreeing span judge. 'That can be it.' behaves the same. 'That will do.' (no 'will' in the reference) gives {'r1': True, 'r2': False}.

**Reviewer's suggested fix:** Count a modal or polarity the item uses as substance only in the terse case the finding asked for: a whole answer, or a span that opens the answer (this keeps the pinned 'No, it can't. Without a base case…'). A tail after other content should not count. Add 'That would be it.', 'That can be it.', 'That will do.' and 'That should do it.' against a context that uses would, can, will and should, all expected None, plus one grade()-level case. If this is kept as a residual, record it in Known gaps with a pin.

## 3. major — `backend/learning/answer_guard.py:1542`

Regression from 823b087, the joiner fix. Ruling point 1 says code rejects a quote that is solely a completeness or credit claim. `_joins` now counts any glue that is not pure sentence punctuation as a joiner, and `_span_ends` then widens the span to the whole whitespace token on the far side. So a claim-only tail glued to the partial answer's last word pulls that word into the span. `_says_more_than_a_claim` counts the pulled-in word as substance, and the quote passes the code check. At ce7e2e6 the same quote returned None. Three kinds of glue trigger it. The em dash and en dash are ordinary prose punctuation, not token joiners. Arrows, '/', '+', '|' and '&' also count. So does sentence punctuation followed by a closing bracket or quote ('.)', '."', ".'"), because the glue set is no longer a subset of `_SENTENCE_GLUE`. That contradicts the commit's own rule that sentence punctuation glued to the next word still ends the span. Credit on such a tail then rests on the span check alone. That is the class the round-4 majors on 7964da5 closed. HANDOFF-a33 Known gaps (line 224) records only the deliberate hyphenated form ('… stops it-both-parts-done'). It has no test, and the coordinator ruling does not accept it. The dash forms are not recorded.

**Evidence:** Offline support_span(quote, answer, min_chars=4, min_share=0.5), context = the eval _RECURSION r2 text + reference. The answer is REC_PARTIAL with the tail glued on. 'Both parts done' in '…stops recursing—both parts done.' gives ce7e2e6=None and HEAD='recursing—both parts done'. The same holds with an en dash, '->', '=>', '+', '|' and '&'. 'Mark both' in '…stops recursing-Mark both.', '…recursing/Mark both.' and '…recursing--mark both.' gives ce7=None and HEAD='recursing-Mark both' and the like. 'Tick both' in '…stops recursing.)Tick both.', "…recursing.'Tick both." and '…recursing."Tick both.' gives ce7=None and HEAD='recursing.)Tick both' and the like. Control: '…recursing.Both parts done.', '…recursing;both…' and '…recursing...both…' still give None. Through the real grade() with tests/grader_fakes: the first run credits r1 on 'stops recursing' and r2 on the tail, and the span check is lenient. '…recursing—both parts done.' gives span messages ['stops recursing—both', 'recursing—both parts done'] and {'r1': True, 'r2': True}. So do '-mark both.', '.)Tick both.' and '—tick both.'. The space-separated control '…recursing. Mark both.' gives spans ['stops recursing'] and {'r1': True, 'r2': False}. test_a_joiner_glued_to_another_word_brings_in_the_whole_token has no case where the pulled-in token lies on the claim side.

**Reviewer's suggested fix:** Run the claim filter only on the quoted run's own words, text[start:start+n] (plus keyed score shapes), not on words a joiner brings in. The widened span is then only what the span check sees, so widening can never turn a claim into substance. Also treat dashes (— – ‒ ―) as sentence glue, and treat glue that contains sentence punctuation ('.)', '."', ".'") as a sentence end, not a joiner. Add parametrized cases against EVAL_REC_CONTEXTS, all expected None: 'Mark both' in '…recursing-Mark both.', 'Both parts done' in '…recursing—both parts done.' and 'Tick both' in '…recursing.)Tick both.'. Add one grade() case showing that r2 is withheld. Then correct the HANDOFF Known-gaps line.
