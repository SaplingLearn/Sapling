## What changed

`learning/evidence.py` holds the spec §5 `Evidence` model under §13 A1: `channel` is always the item's channel (five names, equal to `params.CHANNELS` and `fsrs.RATING_CHANNELS`), and `idk: bool` marks an explicit "I don't know". Validation rejects `idk` with `correct`, bounds `max_rung` to `0..LADDER_MAX_RUNG`, forces `assisted` for any rung ≥ `RUNG_ASSISTED_MIN` (and raises `max_rung` to `RUNG_ASSISTED_MIN` for an assisted answer with no rung), and overwrites `weight` with `evidence_weight(ev)`, the product of the §3.1 weights derived from the flags (0.0 for a correct answer after H4–H6). The `learner_state` table exists (migration `20260927024349_learning_learner_state.sql`, the spec §4 DDL verbatim, `max_streak_unassisted` per §13 A3 included), and so do the eleven evidence columns on `node_mastery_events`. `learning/learner_state.py` reads the table in one batched select, returns each row DECAYED toward `BKT_L0` along its FSRS stability, and never swallows an error. Its `write_state` upserts the BKT/FSRS columns only; the four PKG-06-derived columns are never named. `services/graph_service.py::apply_graph_update` is the single BKT + FSRS writer. A non-empty `graph_update["evidence"]` is validated before any read or write (an `Evidence` instance is re-validated from its dump, like a dict: review round 2 `11aeb02`). Then, after the legacy `updated_nodes` loop (whose `times_studied` writes the evidence mirror now adds to), `_apply_evidence` runs each owned evidence in order: `bkt.update` on the decayed state, counters (a correct same-session re-check counts as an opportunity only), the FSRS transition and due date, `write_state`, the `graph_nodes` mirror (`bkt.tier_for`), one `node_mastery_events` row with `event_type='evidence'`, and one-hop prerequisite propagation at `WEIGHT_PROPAGATION × evidence_weight(ev)`, none for weight-0 evidence (learner_state and mirror only; the target's decay anchor is kept, review round 2 `336b975`). A payload without `evidence` makes the byte-identical table-call trace it made before (pinned). `test_inv_01_single_graph_writer` is real (a regex half, an ast half, and a private-writer half that pins `_apply_evidence` to `apply_graph_update`). Nothing calls the evidence path yet, so every request path is unchanged with the flag on or off.
