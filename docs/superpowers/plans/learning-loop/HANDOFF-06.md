# HANDOFF-06 — zpd-policy

Written by the session that executed `PKG-06-zpd-policy.md`. Read by every later package that depends on 06. Keep every heading, even if the answer is "none".

## What changed

The ZPD policy layer exists as pure code under `backend/learning/`: the hint ladder with the template check pose and the deterministic H2/H4/H6 payloads (`ladder.py`), the ceiling / evidence-by-rung / band-control / wheel-spin policy plus the tutor tier router (`model_tier`, spec §3.5 `LOOP_MODEL_TIER`, A15) and the per-phase context and tool policy (`context_policy`, A18) (`policy.py`), the attempt / rung-dwell / H6 / offer gates with an injectable clock and A5's gate time scale (`gates.py`), and a deterministic answer-leak detector and one-pass stripper (`leak.py`) that matches the reference's n-grams and the item's STRUCTURED final answer — `check_items.final_answer`, which review round 6 added by reopening PKG-04 (spec §13 A34; the coordinator's decision to stop parsing references for a final answer) — and a numeric item's canonical value, in any notation since review round 7; the residuals the owner accepted in round 7 are pinned by tests and listed under Known gaps (every one of them since review round 8, which also made a withheld run take the partner of a bracket it holds unpaired). `sessions.loop_state jsonb NOT NULL DEFAULT '{}'` exists (migration `20260927093843_learning_session_loop_state.sql`) and round-trips through `learning/loop_state_store.py`, which updates by session id, reports a lazy (missing) row as `False`, and never inserts or upserts a `sessions` row (A11); the typed `LoopState` carries every key it does not own through a load/save untouched. The six `zpd.*` event types are in `EVENT_TAXONOMY` and `learning/zpd_events.py` emits them through keyword-only helpers (`zpd.step` carries `tier` and `grader_backend` only when known). Invariants 4 and 5 are asserted and invariant 2 is extended for `ladder.deterministic_content`. Nothing outside `learning/` and `tests/` imports any of it (an ast test proves it, and a second test imports the real app in a clean interpreter and finds no PKG-06 module in `sys.modules`), so flag-off behaviour is byte-identical: the only runtime-visible changes are six extra taxonomy strings, one defaulted jsonb column and (review round 6, PKG-04's reopen) one nullable `check_items.final_answer` column; check-item drafting, which is flag-gated, now asks for, validates and encrypts that final answer. PKG-07 wires the loop tutor through it.

- `backend/learning/gates.py::NON_ATTEMPT_PATTERNS` — exactly `("just tell me", "give me the answer", "idk", "i don't know", "what's the answer")`.
- `::non_attempt_phrases(text) -> tuple[str, ...]` — the A16 ROUTING rule (review round 3, coordinator decision (B): fail toward grading): the `NON_ATTEMPT_PATTERNS` (in their order) that send an explicit submission away from grading, `()` when it is graded. Phrases match whole (lowercase, apostrophes (`'’‘ʼ`´`) deleted, other non-alphanumerics → space: "idkfa" is not "idk"). Any digit, or a relation symbol BETWEEN operands (`F = ma`, `a > b`, `(a+b) = c`; an emoticon `=(` `>.<` `=/` `>_<` is not one), anywhere → `()` — except that in a message holding a request phrase a question label's number is no digit (`_QUESTION_REF`, review round 4: "question 3", "part 2(b)", "q3", "#3", "no. 3", "problems 3-5", "the answer to/for 4b", and the other label words in `gates.py`; linear-time since review round 5; an all-caps "CH" glued to a digit, "CH4", is a formula, never a label), so "what's the answer to part 2" and "just tell me the answer to question 3" are requests; beside an idk phrase alone any digit is still an answer ("idk how to do part 2" is graded). A REQUEST phrase ("just tell me", "give me the answer", "what's the answer") is returned whatever else the message says — the rest of its clause (split at `. , ; : ! ? ( ) [ ] { }`, newlines and `but`) is its object, never an answer — so a request-phrase message with no digit and no operand relation gets no evidence and is never graded ("just tell me, is it the mitochondria?" included; "just tell me, is it 7?" is graded). An IDK phrase ("idk", "i don't know") is returned only when the residue is empty: once the phrases, request objects, `_PLEA` pleas and `_NON_ANSWER` filler are set aside, no word is left, AND no part of a clause is a bare function-word answer (review round 4: a clause residue made only of `_BARE_ANSWER` words — is/isnt, are, was, do/does/doesnt/did/dont, can/cant/cannot, could, will/wont, would, should, have/has/had, might, and/or/not/if, i, a/an — plus `_ANSWER_FRAME` words, with no `_PLEA` n-gram, is an answer: "it isn't, idk", "or? idk", "A? idk", "I think it is, idk" are graded, while "idk, can I get a hint", "idk what to do", "idk, I can't do it" stay idk. Review round 5: `_ANSWER_FRAME` holds subjects, hedges, intensifiers and chat slang (it, that, they, there, im, think, guess, maybe, probably, so, um, well, ok, really, just, actually, too, though/tho, be, to, like, literally, totally, kinda, honestly, lol, man, bro, bruh, ngl, tbh, nah, …), so "not really, idk", "it just does, idk", "it will be idk", "it isnt lol, idk", "nah it isnt, idk" are graded; a first-person statement (im / i am / ive) starts a new part of the clause and a part holding a plea is never a bare answer, so "idk it isnt im not sure" is graded while "idk! I give up" and "idk, can we move on?" stay idk; "i" answers only as the last word of its part ("it's i, idk" graded; "idk, I think" and "idk, I guess I'm stuck" idk); "so" answers after think/guess ("I think so, idk" graded)). `_NON_ANSWER` is filler, function words (the `_BARE_ANSWER` ones among them, filler only beside a help word), help/stuck vocabulary and chat slang ("man", "nah", "bruh", "lmao", "xd", "sry", "forgot", "missed", "lecture", "class", "mean"/"means", "another", "example", "next", "skip", …) and holds NO word that can answer an item alone ("even", "on", "in", "some", "any", "much", "still", "then", "when", "hour(s)", "minute(s)", "start(ed)", "begin", "up", "yes", "no", "true", "false", "hard", "right", "both", "none", "one", "bit", "lot", "lost", "solution", "id", "us", "impossible", "forever"; pinned); such a word is set aside only inside a `_PLEA` n-gram ("no idea"/"no clue", "give up", "too/so/… hard", "this is impossible", "where do I (even) start", "how to start/begin/get started", "for hours", "an hour", "too much", "I'm lost", "a bit confused", "taking forever", "makes no sense", "move on", "walk me through", "I can't do it/this" (review round 4; not when a method follows — by/with/using/via/without — review round 5), "dunno", "don't know", "not sure"). So "even, idk", "on, idk", "in? idk", "hours? idk", "at the start? idk", "I think it's even, idk", "idk maybe 7", "the mitochondria idk" and "x = 7 idk" are `()` (graded); "idk", "I don't know", "idk lmao", "idk =(", "idk, where do I start?" are idk; "just tell me", "man just tell me", "just tell me the steps" are `("just tell me",)`; "idk, just tell me" is `("just tell me", "idk")` (the route checks idk first, A16) and "idk the mitochondria, just tell me" is `("just tell me",)`.
- `::matches_non_attempt(text) -> bool` — `bool(non_attempt_phrases(text))`: the A16 routing test only, NEVER `is_genuine_attempt`'s argument.
- `::has_non_attempt_phrase(text) -> bool` — the HINT-UNLOCKING rule (review round 3, coordinator decision (A): fail closed, no lexicon): True when a `NON_ATTEMPT_PATTERNS` phrase or a `_PLEA` plea occurs anywhere in the message as whole words (same normalisation, over the whole message).
